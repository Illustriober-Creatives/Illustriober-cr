# App Shell (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the marketing `Navbar`/`Footer` from wrapping `/dashboard` and `/admin`, and replace both dashboards' bespoke layout chrome with one shared, branded, full-width `DashboardShell`.

**Architecture:** A route-aware `SiteChrome` client component replaces the unconditional `<Navbar/>{children}<Footer/>` in the root layout, rendering the marketing chrome only outside `/dashboard` and `/admin`. A new `DashboardShell` (sidebar + topbar + full-height content area) is shared by both dashboard layouts, parameterized by role-specific nav items.

**Tech Stack:** Next.js App Router, React, Tailwind (existing design tokens), lucide-react icons.

**Spec:** `docs/superpowers/specs/2026-08-23-dashboard-platform-redesign.md` (§4.1)

## Global Constraints

- Design tokens only: `bg-background` (`#F4EFE5`), `bg-surface` (`#FFFDF8`), `text-foreground` (`#171717`, with `/NN` opacity suffixes), `border-glass-border`, `text-accent` (`#D96800`), `bg-accent/10`, `bg-glass-bg`. No new colors.
- Login/register/forgot-password pages keep the marketing chrome — only `/dashboard/*` and `/admin/*` lose it.
- `AdminGuard` (admin auth redirect) and `ProtectedRoute` (client auth redirect, already correctly redirects `ADMIN` users to `/admin`) are unchanged — this phase only touches presentation, not auth logic.
- The shared shell must not introduce a second Socket.IO connection or otherwise touch the realtime code from PR #74's admin dashboard work.

### Task 1: `SiteChrome` — hide marketing nav/footer on dashboard routes

**Files:**
- Create: `apps/web/src/components/SiteChrome.tsx`
- Modify: `apps/web/src/app/layout.tsx`

**Interfaces:**
- Produces: `export function SiteChrome({ children }: { children: ReactNode }): JSX.Element` — renders `<Navbar/>{children}<Footer/>` for marketing/auth routes, or bare `{children}` for `/dashboard/*` and `/admin/*`.

- [ ] **Step 1: Create the component**

```tsx
"use client";

import { usePathname } from "next/navigation";
import type { ReactNode } from "react";
import { Navbar } from "@/components/Navbar";
import { Footer } from "@/components/Footer";

const CHROME_LESS_PREFIXES = ["/dashboard", "/admin"];

export function SiteChrome({ children }: { children: ReactNode }) {
  const pathname = usePathname();
  const hideChrome = CHROME_LESS_PREFIXES.some(
    (prefix) => pathname === prefix || pathname.startsWith(`${prefix}/`)
  );

  if (hideChrome) {
    return <>{children}</>;
  }

  return (
    <>
      <Navbar />
      <main className="flex-1">{children}</main>
      <Footer />
    </>
  );
}
```

- [ ] **Step 2: Wire it into the root layout**

Remove the now-unused `Navbar` and `Footer` imports from `layout.tsx` if the file no longer references them directly (it doesn't — they're only used inside `SiteChrome` now).

### Task 2: `DashboardSidebar` — shared branded sidebar

**Files:**
- Create: `apps/web/src/components/dashboard/DashboardSidebar.tsx`

**Interfaces:**
- Produces (consumed by Task 3):

    href: string;

  Active-state logic generalizes the exact-match-vs-prefix rule already used for `/admin` in `AdminSidebar.tsx` (tonight's PR #74 fix) to work correctly for ANY nav item whose `href` is a prefix of another nav item's `href` (e.g. `/dashboard` vs `/dashboard/tickets`), not just a hardcoded single case.

- [ ] **Step 1: Create the component**

```tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import type { LucideIcon } from "lucide-react";

export interface DashboardNavItem {
  href: string;
  label: string;
  icon: LucideIcon;
}

interface DashboardSidebarProps {
  navItems: DashboardNavItem[];
  eyebrow: string;
}

function isNavItemActive(pathname: string, href: string, allHrefs: string[]): boolean {
  if (pathname === href) return true;
  if (!pathname.startsWith(`${href}/`)) return false;
  return !allHrefs.some(
    (other) =>
      other !== href &&
      other.length > href.length &&
      (pathname === other || pathname.startsWith(`${other}/`))
  );
}

export function DashboardSidebar({ navItems, eyebrow }: DashboardSidebarProps) {
  const pathname = usePathname();
  const allHrefs = navItems.map((item) => item.href);

  return (
    <aside className="flex w-60 shrink-0 flex-col border-r border-glass-border bg-surface px-4 py-8">
      <Link href="/" className="mb-8 flex items-center gap-2.5 px-2">
        <span className="grid h-8 w-8 place-items-center rounded-full bg-accent font-display text-lg font-bold text-foreground">
          il
        </span>
        <span className="text-sm font-bold tracking-tight text-foreground">Illustriober</span>
      </Link>

      <p className="mb-3 px-2 text-xs font-bold uppercase tracking-[0.18em] text-accent">{eyebrow}</p>

      <nav className="flex flex-1 flex-col gap-1">
        {navItems.map(({ href, label, icon: Icon }) => {
          const active = isNavItemActive(pathname, href, allHrefs);
          return (
            <Link
              key={href}
              href={href}
              className={`flex items-center gap-3 rounded-lg px-3 py-2.5 text-sm font-medium transition-colors ${
                active
                  ? "bg-accent/10 text-accent"
                  : "text-foreground/60 hover:bg-glass-bg hover:text-foreground"
              }`}
            >
              <Icon className="h-4 w-4 shrink-0" aria-hidden="true" />
              {label}
            </Link>
          );
        })}
      </nav>
    </aside>
  );
}
```

### Task 3: `DashboardShell` — sidebar + topbar + full-height content

**Files:**
- Create: `apps/web/src/components/dashboard/DashboardShell.tsx`

**Interfaces:**
- Consumes: `DashboardSidebar`, `DashboardNavItem` from Task 2 (`@/components/dashboard/DashboardSidebar`); `useAuth` from `@/contexts/AuthContext`
- Produces (consumed by Task 4 and Task 5):
  ```ts
  export function DashboardShell(props: {
    navItems: DashboardNavItem[];
    eyebrow: string;
    children: ReactNode;
  }): JSX.Element
  ```
  Renders a full-viewport-height (`min-h-screen`) flex layout: sidebar on the left, a topbar (welcome text + sign-out) and scrollable content area on the right. No dead space below the content regardless of viewport height — this directly fixes the layout bug found in tonight's screenshots (marketing footer appearing after a large empty gap because the old admin shell used `h-screen` inside a layout that also had unrelated chrome above/below it).

- [ ] **Step 1: Create the component**

```tsx
"use client";

import type { ReactNode } from "react";
import { LogOut } from "lucide-react";
import { useRouter } from "next/navigation";
import { useAuth } from "@/contexts/AuthContext";
import { DashboardSidebar, type DashboardNavItem } from "./DashboardSidebar";

interface DashboardShellProps {
  navItems: DashboardNavItem[];
  eyebrow: string;
  children: ReactNode;
}

export function DashboardShell({ navItems, eyebrow, children }: DashboardShellProps) {
  const { user, logout } = useAuth();
  const router = useRouter();

  const handleLogout = async () => {
    await logout();
    router.replace("/login");
  };

  return (
    <div className="flex min-h-screen bg-background text-foreground">
      <DashboardSidebar navItems={navItems} eyebrow={eyebrow} />
      <div className="flex min-h-screen flex-1 flex-col">
        <header className="flex items-center justify-between border-b border-glass-border bg-surface px-6 py-4 md:px-8">
          <div>
            <p className="text-xs font-bold uppercase tracking-[0.18em] text-accent">{eyebrow}</p>
            <p className="mt-0.5 text-sm text-foreground/60">
              {user ? `Welcome, ${user.firstName}` : "Welcome"}
            </p>
          </div>
          <button
            onClick={() => void handleLogout()}
            className="flex items-center gap-2 rounded-full border border-glass-border px-4 py-2 text-sm font-semibold text-foreground/70 transition-colors hover:bg-glass-bg hover:text-foreground"
            type="button"
          >
            <LogOut className="h-4 w-4" aria-hidden="true" />
            Sign out
          </button>
        </header>
        <main className="flex-1 overflow-y-auto">{children}</main>
      </div>
    </div>
  );
}
```
